## Additional functional paths

Direct reservations can be entered from the calendar. Creation enforces property currency, valid dates and idempotency, shows overlaps with protected dates and buffer days for acknowledgement, encrypts guest fields, and links a conversation. Direct email replies require Resend; inbound email requires the documented adapter. This is an operational reservation record, not a public payment/booking storefront.

Owners can create and revoke co-host access; users can change passwords, and an administrator can perform audited recovery. Photo uploads and feed URLs are protected rather than public assets. CSV export escapes formula-leading values. Unknown external-send outcomes are manually reconciled from Activity with a recorded reason.

## Validation and remaining operator work

The repository includes domain, fixture, property-based, encryption and PGlite database tests (`pnpm test`), integration tests against real PostgreSQL through the runtime role (`pnpm test:integration`), and targeted Chromium checks against the production build (`pnpm test:browser`). They do not establish managed-provider networking, production latency or hosted scheduling. Run the full gate list in [CONTRIBUTING.md](../CONTRIBUTING.md) on the exact commit being deployed; [RELEASE_CHECKS.md](RELEASE_CHECKS.md) records the latest run.

No production credentials were supplied with the request. Live OTA accounts, a deployed partner bridge, SMS delivery, inbound/direct email, browser push delivery, private cloud storage, and hosted OpenAI calls need operator-connected acceptance checks. UI and unit/database checks are not substitutes for those checks.

The release also lacks MFA/SSO, PII retention periods and erasure beyond permanently deleting a removed property (no per-guest or account deletion), bulk key re-encryption, a public booking/payment checkout, provider delivery-status callbacks, and smart-lock programming. These are not silently simulated. The specified foundation can be extended through the server services and versioned migrations; future changes still require schema, privacy, UX, and performance review.

See [DEPLOYMENT.md](DEPLOYMENT.md), [INTEGRATIONS.md](INTEGRATIONS.md), and [OPERATIONS.md](OPERATIONS.md) for concrete setup and operational boundaries.
