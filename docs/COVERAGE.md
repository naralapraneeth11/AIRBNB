## Additional functional paths

Direct reservations can be entered from the calendar. Creation enforces property currency, valid dates, buffers, idempotency, encrypted guest fields, and a linked conversation. Direct email replies require Resend; inbound email requires the documented adapter. This is an operational reservation record, not a public payment/booking storefront.

Owners can create and revoke co-host access; users can change passwords, and an administrator can perform audited recovery. Photo uploads and feed URLs are protected rather than public assets. CSV export escapes formula-leading values. Unknown external-send outcomes are manually reconciled from Activity with a recorded reason.

## Validation and remaining operator work

The package includes focused domain, encryption, iCal, and PostgreSQL migration/security tests. Database tests use PGlite's embedded PostgreSQL engine; they do not establish managed-provider networking, Prisma pool behavior, production latency, or Vercel scheduling. Run `pnpm typecheck`, `pnpm test`, and `pnpm build` on the exact commit being deployed.

No production credentials were supplied with the request. Live OTA accounts, a deployed partner bridge, SMS delivery, inbound/direct email, browser push delivery, private cloud storage, and hosted OpenAI calls need operator-connected acceptance checks. UI and unit/database checks are not substitutes for those checks.

The release also lacks MFA/SSO, self-service email password recovery, automatic PII-retention/erasure tooling, bulk key re-encryption, a public booking/payment checkout, provider delivery-status callbacks, and smart-lock programming. These are not silently simulated. The specified foundation can be extended through the server services and versioned migrations; future changes still require schema, privacy, UX, and performance review.
